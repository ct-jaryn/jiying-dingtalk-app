# jiying-dingtalk-app

只给自己用的即应应用。钉钉里和你相关的新消息会原文推送到应用单聊；你在这条单聊里发指令时，Agent 通过 `dws` 操作钉钉聊天。

## 配置

```bash
cp config.example.yaml config.yaml
```

填入 Anthropic 兼容接口、即应应用接入信息和你的即应用户 ID。`config.yaml` 不要提交。

## 运行

需要 Node.js >= 20，以及已安装并登录的 `dws >= 1.0.65`。此版本支持同时订阅私聊、群聊和 @ 事件；首次使用先运行 `dws auth login` 完成钉钉授权。

```bash
npm install
npm start
```

用 Ctrl+C 停止，不要 `kill -9`。

## 行为

- 推送：私聊、群里的 @你和 @所有人。被 @ 时即使群开启免打扰也通知，原文直接转发，不经过模型。
- 群聊监控使用长连接。专用 @ 事件直接通知；群全量事件同时按消息 ID 核对当前用户的提及记录，补偿专用事件未送达或提及索引延迟。不会按正文中的同名姓名猜测。
- 通知先保存到 `data/push-outbox.json`，成功发送后再标记完成；即应断线会自动重连并重试，重启后继续待发消息。长消息逐块保存进度，两路订阅重复收到同一消息时合并。
- 待核对的群消息保存在 `data/pending-mentions.json`；查询失败或分页未完成会保留重试。普通群消息在完整核对窗口结束后清理。远端发送已成功但本地进度尚未落盘的崩溃窗口，仍可能重复通知。
- 主动：只处理你在应用单聊里发来的消息。先贴 👀，再同步正在思考、正在调用工具、正在生成回复。
- 会话始终保持同一个。每次请求带最近 6 句可见记录和当前指令，单次最多调用工具 25 轮。
- 发消息和回复直接执行，不二次确认。

## 排查实时通知

日志中的“群消息已接收 → 群聊@已确认 → 通知已送达”分别表示事件进入、提及核对成功、即应已接受通知。专用 @ 事件直接走“通知已入队 → 通知已送达”。只有订阅就绪不能证明实际消息已投递。

`dws event status --event user_im_message_receive_at --format json` 可查看消费者计数。需要测试时，由同事或另一个账号在群里 @你；当前账号自己发送的消息会被上游过滤。

## 测试

运行 `npm test`。测试覆盖提及匹配、事件解析、持久化、通知去重、断线重试和本地 WebSocket 集成，不需要真实账号凭据。
