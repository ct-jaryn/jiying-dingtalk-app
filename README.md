# jiying-dingtalk-app

只给自己用的即应应用。钉钉里和你相关的新消息会原文推送到对应的即应话题；你在应用单聊里发指令时，Agent 通过 `dws` 操作钉钉聊天。

## 使用方式

先在即应里创建一个应用，并把可见范围设成仅自己可见。即应的可见范围有三种：创建者、指定用户、公开。这里要选创建者，不要选指定用户或公开。这样别人看不到这个应用，也不能在群里把它拉进来指挥。

创建后打开该应用的「应用接入信息」，抄下这三项，后面写入 `config.yaml`：

- WebSocket 地址，填到 `magicchat.ws_url`
- 应用 ID，填到 `magicchat.app_id`
- 连接密钥，填到 `magicchat.app_secret`

再找到你自己的即应用户 ID，填到 `magicchat.user_id`。推送只发给这个人，也只处理这个人在应用单聊或已关联话题里发来的消息。密钥只放在 `config.yaml`，不要提交到仓库。

需要 Node.js >= 20，以及已安装并登录的 `dws >= 1.0.65`。此版本支持同时订阅私聊、群聊和 @ 事件。登录的必须是你要接收通知的那个钉钉账号。安装和登录命令见下文。组织如果还没开 CLI 权限，需要管理员在钉钉开发者平台开启。

配置写好后，在仓库目录启动：

```bash
npm install
npm start
```

看到「即应已连接」和钉钉实时监听就绪的日志就可以用了。这个进程要一直开着。停止时用 Ctrl+C，不要 `kill -9`，否则钉钉上的个人事件订阅可能退不掉。

用的时候打开这个应用的单聊和它创建的话题，不要在即应的群里 @ 它。群消息会被直接丢掉。

它有两种工作方式：

- 推送：私聊、@你和 @所有人始终转发；默认还推送所有未开免打扰的群消息。把 `push.all_group_messages` 设为 `false` 后，只保留私聊和提及。`push.muted_conversations` 默认 `false`，设为 `true` 后也同步免打扰群的普通消息；被 @ 时无论该配置如何，仍会通知。推送不经过模型，只进对应话题：私聊只发正文，群聊写成同一行「**发送人**：正文」。图片以即应图片消息发进话题，纯图片群消息的说明也带发送人。
- 主动：你在应用单聊里发指令。应用先在你的消息上贴 👀，表示已收到，然后显示正在思考、正在调用工具、正在生成回复。它可以用 `dws` 查未读、查 @你、搜消息、读会话、找人找群、发私聊、发群消息、回复某一条。发消息和回复会直接执行，不再二次确认。撤回没有开放。

一个钉钉会话对应一个话题。话题还不存在时，先在应用单聊发一句钉钉会话名，用它创建话题，之后的消息进入话题。对应关系保存在本地 `data/topics.json`，重启后继续使用。你在话题里回复的文字和图片会直接发回那个钉钉会话，不经过模型；发送成功后在即应原消息上贴 ✌️ 确认。应用发送的钉钉消息会附加「使用即应发送」文字表情。

私聊对象以钉钉会话 ID 校验，主动在钉钉发出的消息也归入真实对方的话题，并标成「**我**：正文」。无法确认联系人时保留通知重试，避免发给错误对象。旧版本创建的私聊话题会在启动及回复前校验并修正收件人；即应暂不支持机器人修改已有话题标题，修正后会在原话题内说明真实对象，历史消息继续保留。

主动对话始终是同一个 session，不会每句话新开一次。每次请求带上最近 6 句可见记录和你这次的指令。单次最多调用工具 25 轮，到上限就用已有结果回复。

## 实时通知与恢复

群聊监控使用长连接。专用 @ 事件直接通知；群全量事件同时按消息 ID 核对当前用户的提及记录，补偿专用事件未送达或提及索引延迟。不会按正文中的同名姓名猜测。

通知先保存到 `data/push-outbox.json`，成功发送后再标记完成；即应断线会自动重连并重试，重启后继续待发消息。长消息逐块保存进度，两路订阅重复收到同一消息时合并。不同会话最多并行投递 3 条，同一会话的在途通知保持串行；媒体任务和旧重试分别最多占用一个工作位，优先处理新通知，避免失败图片堵住其他会话。

图片的权限不足、资源失效、媒体 ID 无效或格式不支持会停止原图重试；已识别资源的其他图片下载故障最多尝试 5 次，元数据暂不可用时仍保留原事件退避重查。原始事件和失败分块保存在本地 outbox 的 `failed` 数组，话题里发送失败说明并提示到钉钉查看；已送达的正文不重发，也不会把失败原图标记为完整送达。即应断线等通用传输故障继续保留原分块重试，不消耗图片重试次数。重复错误仅在少数重试节点写简短日志。

`dws` 的只读调用或带幂等键的发送、回复遇到证书、网络等可重试错误时，在总超时预算内按 1、2、4、8、16 秒间隔最多重试 5 次。明确标记为不可重试的错误直接返回；没有幂等键的写操作不会自动重复执行。

从即应发送到钉钉的消息会按真实发送回执记入 `data/outbound-sent.json`。同一消息的钉钉事件不会再转发回即应；事件先于回执到达时也会等待核对。只按消息 ID 和会话识别，其他人发送相同内容仍正常同步。

待核对的群消息保存在 `data/pending-mentions.json`；查询失败或分页未完成会保留重试。普通群消息在完整核对窗口结束后清理。远端发送已成功但本地进度尚未落盘的崩溃窗口，仍可能重复通知。

## 安装 dws

应用通过本机的 `dws` 收钉钉事件和操作聊天。官方仓库是 [dingtalk-workspace-cli](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)。安装后确认版本不低于 1.0.65。

国内网络建议用 npm 镜像：

```bash
npm install -g dingtalk-workspace-cli --registry=https://registry.npmmirror.com
dws --version
```

也可以用安装脚本。能访问 GitHub 时：

```bash
curl -fsSL https://raw.githubusercontent.com/DingTalk-Real-AI/dingtalk-workspace-cli/main/scripts/install.sh | sh
```

GitHub 不稳定时改用 Gitee 镜像：

```bash
curl -fsSL https://gitee.com/DingTalk-Real-AI/dingtalk-workspace-cli/raw/main/scripts/install.sh | DWS_GITEE_REPO=DingTalk-Real-AI/dingtalk-workspace-cli sh
```

安装后登录接收通知的那个钉钉账号。浏览器会打开，选择组织并授权：

```bash
dws auth login
dws auth status
```

无图形界面时用 `dws auth login --device`。组织如果还没开 CLI 权限，需要管理员在钉钉开发者平台开启。

## 配置

配置文件是仓库根目录的 `config.yaml`。它包含密钥，已在 `.gitignore` 中，不要提交。

```bash
cp config.example.yaml config.yaml
```

字段如下。

`anthropic` 是主动模式调用的模型，协议为 Anthropic Messages。

| 字段 | 说明 |
| --- | --- |
| `base_url` | 接口地址。官方是 `https://api.anthropic.com`；使用兼容网关时填网关地址，程序会请求 `{base_url}/v1/messages`。如果地址本身以 `/v1` 结尾，则不会再重复追加。 |
| `model` | 模型名称，原样传给接口。 |
| `api_key` | 模型密钥，放在请求头 `x-api-key`。 |

`magicchat` 是即应应用的接入信息。在即应的「应用接入信息」里复制前三项。应用用独立身份连接，不会继承创建者权限。

| 字段 | 说明 |
| --- | --- |
| `ws_url` | WebSocket 地址，形如 `wss://<主机>/api/app/ws`。 |
| `app_id` | 应用 ID。 |
| `app_secret` | 应用连接密钥。只放在这个文件里，不要写进客户端或仓库。 |
| `user_id` | 你自己的即应用户 ID。推送只发给这个人；也只处理这个人在应用单聊或已关联话题里发来的消息。 |

`agent` 可以省略，省略时使用下列默认值。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `max_rounds` | `25` | 你发来一条消息后，模型最多连续调用工具的轮数。到上限后用已有结果回复，不新开 session。 |
| `max_context_tokens` | `100000` | 单次请求的上下文估算上限。超过后压缩更早的对话和旧工具结果，最近 6 句和当前这一轮保持原样。 |

`push` 控制群消息推送范围。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `all_group_messages` | `true` | 同步普通群消息，默认跳过免打扰群。设为 `false` 时只同步私聊、@你和 @所有人。 |
| `muted_conversations` | `false` | 与 `all_group_messages: true` 一起使用时，也同步免打扰群的普通消息。此项不影响私聊、@你和 @所有人的通知。 |

## 排查实时通知

日志中的“群消息已接收 → 群聊@已确认 → 通知已送达”分别表示事件进入、提及核对成功、即应已接受通知。专用 @ 事件直接走“通知已入队 → 通知已送达”。只有订阅就绪不能证明实际消息已投递。

`dws event status --event user_im_message_receive_at --format json` 可查看消费者计数。需要测试 @ 通知时，建议由同事或另一个账号在群里 @你；应用自身发出的钉钉消息会按发送回执过滤回流。

## 测试

运行 `npm test`。测试覆盖提及匹配、事件解析、持久化、通知去重、断线重试、话题映射、图片双向转发、发送来源标记和本地 WebSocket 集成，不需要真实账号凭据。
